# Гайд по WebSocket в нашем проекте (WebChatApplication)

## 1. Введение: Зачем нам это?
Обычный HTTP (REST) работает как рация:
*   Клиент: "Дай новые сообщения".
*   Сервер: "Вот, держи".
*   Клиент: *молчит*.
*   Сервер: *молчит*.

Чтобы узнать о новом сообщении, клиенту нужно постоянно спрашивать ("Ну что, есть? А сейчас?"). Это нагружает сервер и сажает батарею телефона.

**WebSocket** — это телефонный звонок.
*   Клиент звонит серверу.
*   Соединение **не разрывается**.
*   Как только сервер получает сообщение, он **сразу** говорит в трубку: "Тебе письмо!".

## 2. Архитектура: STOMP и Брокер
Чистый WebSocket — это просто поток байтов. Чтобы не придумывать свой велосипед ("первая буква - тип, вторая - длина..."), мы используем протокол **STOMP** (Simple Text Oriented Messaging Protocol).

Он похож на HTTP. Сообщения выглядят так:
```
SEND
destination:/app/chat
content-type:application/json

{"text":"Привет!"}
^@
```

### Роль Брокера (Message Broker)
Внутри Spring работает "почтальон" (SimpleBroker).
1.  **Android** подписывается на "ящик": `/user/queue/messages`.
2.  **Сервер** кладет письмо в этот ящик.
3.  **Брокер** мгновенно доставляет письмо Android'у.

## 3. Как это реализовано у нас

### А. Конфигурация (`WebSocketConfig.java`)
Мы настроили "телефонную станцию":
1.  **Endpoint `/ws`**: Сюда Android стучится для начала разговора (Handshake).
2.  **Prefix `/app`**: Если Android хочет что-то сказать серверу, он шлет на адреса, начинающиеся с `/app` (например, `/app/chat`).
3.  **Prefix `/user`**: Если сервер хочет отправить что-то конкретному юзеру, он шлет в `/user/...`.

### Б. Безопасность (`WebSocketConfig` + Interceptor)
Самое сложное — понять, **кто** звонит.
1.  Android при подключении (в команде `CONNECT`) передает заголовок:
    `Authorization: Bearer <JWT_TOKEN>`
2.  Наш `ChannelInterceptor` перехватывает это.
3.  Проверяет токен.
4.  Если токен валиден, прикрепляет пользователя к сессии сокета.
    *   Теперь сервер знает: "Это соединение принадлежит User ID 5".

### В. Обработка сообщений (`ChatController.java`)
```java
@MessageMapping("/chat") // Слушаем адрес /app/chat
public void processMessage(@Payload MessageDtoRequest request, Principal principal) {
    // 1. Сохраняем сообщение в БД (PostgreSQL)
    // 2. Отправляем получателю через Брокер
    messagingTemplate.convertAndSendToUser(
        recipientUsername,      // Кому: "user_2"
        "/queue/messages",      // Куда: в его личную очередь
        messageDto              // Что: само сообщение
    );
}
```

## 4. Шпаргалка для Android (Клиентская часть)

Для реализации на Android используй библиотеку **StompProtocolAndroid** или **OkHttp**.

### Шаг 1. Подключение
*   **URL:** `ws://<SERVER_IP>:8080/ws`
*   **Headers:** При подключении (connect) обязательно передай заголовок `Authorization`.

### Шаг 2. Подписка (Слушаем входящие)
Сразу после подключения подпишись на свою личную очередь.
*   **Topic:** `/user/queue/messages`
*   **Что придет:** JSON объект `MessageDtoResponse` (когда кто-то напишет тебе).

### Шаг 3. Отправка (Пишем другу)
Чтобы отправить сообщение:
*   **Destination:** `/app/chat`
*   **Body (JSON):**
    ```json
    {
      "recipientId": 123,
      "context": "Привет, как дела?"
    }
    ```

### Полный цикл (Flow)
1.  User A и User B подключаются к сокету.
2.  User B подписывается на `/user/queue/messages`.
3.  User A шлет JSON на `/app/chat` (где `recipientId` = ID User B).
4.  Сервер сохраняет сообщение.
5.  Сервер пересылает сообщение в канал User B.
6.  User B видит сообщение мгновенно.

## 5. Частые проблемы

1.  **401 / 403 при подключении:**
    *   Проверь, что JWT токен жив.
    *   Проверь, что передаешь `Bearer ` (с пробелом).
    *   В Android библиотеках хедеры иногда нужно добавлять особым образом в объект `ConnectHeaders`.

2.  **Сообщения не доходят:**
    *   Убедись, что получатель **подписался** (`SUBSCRIBE`) на `/user/queue/messages`.
    *   Убедись, что сервер отправляет на правильный `username`. Если в базе логин `sweezy`, а ты шлешь на `Sweezy` (с большой буквы) — не дойдет.

3.  **CORS ошибка:**
    *   Мы разрешили `setAllowedOriginPatterns("*")`, так что проблем быть не должно.
